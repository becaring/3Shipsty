## First implementation boundary

Implement an owned, source-locked **XDK graphics compatibility slice against M's existing interfaces**: all rendering/window virtual signatures; M's decoder and Prism shader builder projected for VS2010; native Xenos backend including six textures and complete current framebuffer operations; real pinned ImGui backend integration. First compile the interface/provider/native TUs and execute a shader/layout differential corpus, then connect the unchanged current interpreter/window flow. This is an early validation boundary, not a reduced final product or permission to omit features.

S's standalone donor files are not its production backend: `prepare_graphics_xdk.py` transforms the old native core and appends `native_extensions.inc`. Reviewing/copying only `graphics/donor/gfx_xenos.cpp` would miss required six-slot, independent-clear and modern wrapper behavior. Likewise, running the reference generator would write into the reference tree and target the wrong pinned API. Recreate narrowly audited projections in the owned tree.

Excluded from reuse: BattleShip/SSB game sources, scene/display-list policy, SSB color-image/Z redirection and persistent pillarbox semantics, BattleShip-specific shader-ID packing, postprocess/slang additions absent from M, and obsolete SoH 4.0.5 application/window/frame-driver replacements. Native hardware mechanisms and compiler compatibility algorithms may be adapted independently, without importing those behaviors.
