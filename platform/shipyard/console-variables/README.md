# Current ConsoleVariable

Generic Shipyard A/B/E adaptation, generated by
`tools/shipyard/prepare_console_variables.py`; exact normalized input hashes are
checked before any output. The complete current ConsoleVariable.cpp compiles
for Xenon. No replacement variable store or reduced persistence path is used.

- Scoped type stays a distinct type. Every reached CVar allocation uses
  `make_shared<CVar>()`; the generated constructor explicitly retains its
  value-initialized integer type and null string union member.
- Current recursive JSON traversal, typed conversions, RGBA/RGB handling,
  registration, copy/clear, Save/Load and legacy cvars.cfg migration remain.
- Range loops use real container/proxy iterators. JSON's items proxy is handled
  directly because it does not expose the standard container iterator typedefs.
- Only fs::path arguments to the five DiskFile stream constructors become
  native narrow strings. Existing string overloads remain unchanged. Path uses
  the already verified filesystem namespace boundary and real StringHelper.
- Logging and projected relative includes are made explicit.

Build: `python -B tools/shipyard/prepare_console_variables.py --build`.
Evidence: `scratch/console-variables-xdk/xdk/build.json` and its compile log.
Full CVar persistence execution awaits live Context integration; this is native
object evidence, not a behavioral parity or save-system completion claim.
Existing upstream cross-type string ownership behavior has not been rewritten.
