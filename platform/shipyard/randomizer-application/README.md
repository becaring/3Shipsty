# Complete modern randomizer application

The pinned full 35 sources retain randomizer initialization, gameplay hooks,
messages, entrance handling, plandomizer, check/item/entrance trackers, save-file
integration and the real randomizer menu. Seed generation, content and regions
have separate complete providers; ShuffleSpeak belongs to the speech provider.
No game path, menu, item, location or hook is substituted.

`prepare_randomizer_application.py` checks locked source identities and generates
copies under `scratch/randomizer-application-xdk`. A/B adaptations lower actual
container, aggregate, designated and default-member initializers to explicit
typed construction. Original ordering, defaults, conditions, string bytes and
callback bodies remain. Canonical headers and existing compatibility wrappers
provide filesystem iteration, enum traits, JSON and GUI APIs. Plandomizer builds
each complete JSON right-hand value before assigning the original destination.
An XDK inference defect requires a named GetItemEntry local before returning a
macro aggregate; the real type and value remain intact.

D: the real generation worker uses Shipyard's native joining_thread. Shutdown
joins any joinable worker, including unfinished generation, before clearing its
completion flag. The real DeinitOTR calls this before destroying services used by
generation. The original generator, RNG, settings and completion hooks remain.
This is application lifecycle integration, not a second generation system.

All syntax projection and initialization policy here is 3Shipsty-specific.
Existing native threading/filesystem primitives are generic Shipyard. The source
changes introduce no byteswaps: these tables and structures are runtime-native
data; existing serialized archive and save boundaries retain ownership.

The checks retain 462 original function definitions, 183 hooks and 7,133
execution string literals. Original/projected host runs compare the real entrance
shuffle and entrance tracker tables, all four item-tracker dungeon layouts, and
8,196 cases from the four actual Plandomizer JSON expressions, including signed
extremes and embedded NUL input. The digest is 2900747072078016156. A separate
contract executes the actual projected join function with native thread ownership
for idle, unfinished and repeated shutdown. Full 35-unit XDK source/object hashes
are checked, and generation is deterministic.

This establishes translation evidence only. Real seed generation, tracker UI,
gameplay hooks and lifecycle still require the genuine application in Xenia;
there is no target execution or hardware claim.
