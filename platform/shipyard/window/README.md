# Current shared window and GUI ownership

Generic Shipyard A/B/C adaptations, generated by `tools/shipyard/prepare_window.py`.
All input hashes are normalized UTF-8/LF and checked before outputs are written.
Upstream tracked sources remain unchanged.

Five full current TUs compile: Window, MouseStateManager, GuiElement, GuiWindow,
and GuiMenuBar. Window retains its actual Config/GUI/mouse owners and all current
methods. Empty delegating constructors become member initialization plus one
generated copy of the original target body. All four Window constructors restore
`mLastScancode = -1`; MouseStateManager restores all four original defaults.
The default GuiWindow constructor explicitly preserves zero flags for value
initialization; its other constructors initialize the exact original members.

Gui.h retains every method/member and the real GuiTextureMetadata value type.
Implementation-only includes are replaced with forward declarations, including
SDL_Renderer, which is only a pointer in the preserved desktop init-data union.
Gui.cpp must include its actual ConsoleWindow/InputEditor/Stats/GameOverlay,
controller device-event handler, GuiWindow/MenuBar, icons and Fast Texture
definitions directly when projected. No default window has been removed.

`python -B tools/shipyard/prepare_window.py --build` builds all five native TUs.
`python -B tools/shipyard/tests/test_window.py` compares the full current original
and projected GuiElement implementations: initial state, failed initialization
and retry, one-time initialization, virtual visibility dispatch, hidden updates.
This does not execute native presentation, GUI construction or menu rendering.

The projected Window.h takes precedence over the earlier declaration-only
configuration copy. Final manifest composition must enforce that ordering.
