# Complete modern application extras

This batch projects thirteen complete translation units from stable Shipwright 9.2.3 / cb71e22a79bc5d1f688fa881795bbd93094895fc. `inventory.json` records their original pending manifest entries. `sources.lock.json` fail-closes source drift, including the two complete local header projections (Presets and Mouse) and relevant declaration dependencies. No upstream or reference source is edited.

## Included implementations

- Presets/Presets.cpp: complete preset discovery, real archive JSON resources, merging, configuration application and widgets.
- TimeDisplay/TimeDisplay.cpp and timesplits/TimeSplits.cpp: complete actual windows, timers, split catalog and persistence.
- boss-rush/BossRush.cpp: complete modern settings, save setup, menu, arena, hook and gameplay logic.
- controls/InputViewer.cpp and controls/Mouse.cpp: complete current display and platform input paths.
- customequipment.cpp: complete resource fallback, graphics patch and equipment hooks.
- debugconsole.cpp: complete command handlers and registrations.
- gameplaystats.cpp, mod_menu.cpp, mods.cpp, nametag.cpp, timesaver_hook_handlers.cpp: complete current application features and registration.

## Narrow adaptations

| Boundary | Adaptation and preserved contract |
|---|---|
| A/B: aggregate/container initialization | Actual vectors/maps/pairs/arrays use temporary backing arrays, constructors or member assignments. Every original table entry, order, type and value remains. Value-initialized UI options use canonical ValueInit support; actual widgets and SearchWidget references remain intact. |
| A: lambdas | Explicit return types where the old compiler cannot infer them. The noncapturing BossRush OnLoad callback becomes a named function so nested hook macro source directives remain valid. Hook execution and registration order are retained. |
| B/E: filesystem | Existing xbox_compat::filesystem supplies the same path/directory API. Directory ranges become explicit iteration of the genuine iterator, including original recursive traversal options. |
| B/F: JSON | Actual object members are assigned in the original order instead of initializer-list JSON construction. FileType and SplitStatus explicitly serialize their integral representation. Time splits deliberately serialize INACTIVE, matching upstream; all ten split fields and four tint channels remain. JSON .items loops use actual key/value iterators; preset recursive update still calls update(value, true). |
| B: console/save-state types | Every actual CommandEntry preserves its handler, description and arguments, including optional flags. Actual SaveStateRequest constructor and scoped-enum GetValue replace unsupported aggregate/switch syntax. |
| B: resource/UI ownership | Explicit canonical current providers replace desktop umbrella includes. ResourceMgr graphics commands, controller paths, UI windows and application registrations are unchanged. |
| A: UTF-8 | Existing literal escaping preserves bytes under XDK's source code page. No resource endian conversion is introduced. |

Custom-equipment initializer_list parameters become local vectors built from the identical original rows. Their callback lifetime remains bounded to the original call. PresetInfo constructor preserves value-initialized section flags for map insertion and reset. Only source syntax/provider boundaries change; there is no replacement gameplay, UI, asset or save service.

## Rebuild and verification

From the workspace root:

```powershell
C:/Python313/python.exe -B tools/shipyard/prepare_application_extras.py --build
C:/Python313/python.exe -B tools/shipyard/test_application_extras.py
```

Generation without `--build` is deterministic. `--only <substring>` and `--failed` are available for local diagnosis; use the complete build for final validation. Dependencies must already be generated by their owners; this generator never regenerates shared dependencies.

Native recipes, source/object SHA-256 values and PowerPC machine checks are in `scratch/application-extras-xdk/xdk/build.json`. Logs are alongside each object. `manifest.json` records generated files and projection-helper hashes. `verification.json` records original/projected source inventory, console command metadata, host comparisons, native evidence and reproducibility.

The checks retain 232 original functions, 260 CVar references, 26 hook calls, 20 exact graphics command expressions and 2,435 original string occurrences. Host programs use actual original and projected tables/functions, actual SplitObject/JSON types and the real projected JSON backend. They compare all twelve boss settings (36 choices across three languages), 128 preset-section masks via actual ParsePreset, 142 split definitions, 15 popup groups and 512 full split serialization round trips; malformed string fields still reject with JSON type error 302. Source comparison also checks every console handler/description/argument tuple.

## Integration

Use `prepare_application_extras.includes()` before the existing application includes; add the thirteen recipes from `xdk/build.json` to the native source/object inventory. The canonical existing application-gui window declarations, application-windows helper, current randomizer-context Kaleido header, app-services ActorDB, ShipInit, UIWidgets and menu providers are reused. Complete projected Presets.h and Mouse.h are under `scratch/application-extras-xdk/generated/soh`.

No new runtime startup hook or shared-provider change is required. Existing full window/feature registration functions are retained for normal application startup. The compiled objects have not been linked or run in Xenia by this batch; this is native translation and host semantic evidence, not application bring-up or hardware validation.
