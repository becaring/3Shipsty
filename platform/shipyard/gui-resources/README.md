# Current GUI resources and image decoding

Generic Shipyard A/B/F adaptations are generated by
`tools/shipyard/prepare_gui_resources.py`. Seven full native TUs compile:
Font, FontFactory, GuiTexture, GuiTextureFactory, GameOverlay, Fast::Texture,
and stb_image's real C implementation.

stb commit `0bc88af4de5fb022db643c2d8e549a0927749354` is the exact revision
specified in current LUS cmake/dependencies/common.cmake. Its clean owned
snapshot has a verified receipt in dependencies.lock.json. No decoder format
or SIMD capability is overridden; upstream selects its portable PPC path.

The inherited Resource constructors and original member defaults are made
explicit. Real factory validation, reader ownership, image decode failure,
font bytes, texture dimensions and allocation/free paths remain unchanged.
GameOverlay keeps its complete implementation: font loading/registration,
notifications, settings, timing and draw behavior. Constructor defaults removed
from the earlier declaration projection are now restored by its actual TU.
Its original loops, records and scoped-enum switches are mechanically lowered.

`tests/test_gui_resources.py` executes the full original/projected factory and
resource implementations with the same pinned decoder. It compares binary
font bytes (including zeros/high bytes), a 2x2 RGBA PNG with alpha, invalid image
and format rejection, valid-metadata Fast Texture defaults, pointer ownership,
and exact upstream sizes. Both reader endian settings give identical bytes.
GUI texture GetPointerSize intentionally retains upstream's encoded input size.

Endian boundary: PNG/JPEG encoded data has its own byte-order parser; decoded
RGBA is a byte vector. Raw font bytes are opaque. Neither is swapped according
to the resource BinaryReader setting. This host check is not PPC execution.

Commands:

    python -B tools/shipyard/prepare_gui_resources.py --build
    python -B tools/shipyard/tests/test_gui_resources.py

Evidence: scratch/gui-resources-xdk/{manifest.json,xdk/build.json,verification.json}.
No live GameOverlay/ImGui draw, native resource mounting or Xenia claim.
The resource layer's GameOverlay.h supersedes the declaration-only Context copy;
GuiTexture.h is shared through the same window projection function. Final
header composition must enforce those choices consistently across all TUs.

Inherited GameOverlay paths still need execution review: TEXT overlay drawing
frees a string's c_str pointer, and TextDraw reuses formatted text as a format.
No silent source fix or omitted notification feature was introduced here.
